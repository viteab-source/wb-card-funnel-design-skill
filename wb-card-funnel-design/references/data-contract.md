# Контракт выборки и ранжирования

Читайте перед созданием `sample-metadata.json`, `competitors.csv` и запуском `scripts/rank_sample.py`. Шаблоны находятся в `assets/`.

Это отдельный legacy-контракт для явно выбранного 90-дневного MPStats/отзывного benchmark. Он не является обязательным входом скила и не применяется к XLSX WB, «Джему» или обычному визуальному shortlist. Для них используйте `interview.md` и `input-requirements.md`. `research_complete` здесь описывает только полноту этого benchmark, а не готовность всего проекта.

## Паспорт запуска

`sample-metadata.json` фиксирует `sample_id`, запрос, начало и конец наблюдения, часовой пояс, регион, устройство, ширину viewport, гостевой/авторизованный режим, сортировку, фильтры, аналитический период, источник сбора, статус и причину блокировки.

`sample_status` принимает `ready`, `partial` или `blocked`. При пустой выборке допустим только `partial` либо `blocked` с заполненным `block_reason`.

## CSV

Обязательные колонки:

| Поле | Значение |
|---|---|
| `rank` | исходная позиция в выдаче, целое от 1 |
| `nm_id` | уникальный артикул WB |
| `query` | точный поисковый запрос |
| `observed_at` | ISO 8601 со смещением часового пояса |
| `period_start` | начало аналитического периода, `YYYY-MM-DD` |
| `period_end` | конец аналитического периода, `YYYY-MM-DD` |
| `source_url` | ссылка на карточку |
| `sponsored` | `true`, `false` или `unknown` |
| `main_image_ref` | URL или локальный путь снимка обложки |

Опциональные числовые колонки:

| Поле | Значение |
|---|---|
| `review_count` | видимое общее число отзывов на дату снимка |
| `reviews_90d` | отзывы с датой внутри периода |
| `mpstats_sales_90d_est` | оценка продаж MPStats за период |
| `mpstats_revenue_90d_est` | оценка выручки MPStats за период |

Для `reviews_90d` обязательна колонка `reviews_90d_coverage` со значением `complete`, `partial` или `unknown`.

Колонки визуального анализа: `shot`, `angle`, `background`, `product_share`, `text_density`, `human_presence`, `proof`, `palette`, `readability`. Дополнительные поля: `brand`, `title`, `price`, `rating`, `value_claim`, `notes`.

## Правила ранжирования

1. При полном заполнении `mpstats_sales_90d_est` у всех строк: продажи по убыванию, затем оценка выручки, число отзывов, исходная позиция и `nm_id`.
2. Иначе, при полном `reviews_90d` и `reviews_90d_coverage=complete` у всех строк: отзывы за период по убыванию, затем общее число отзывов, исходная позиция и `nm_id`.
3. Иначе: `ranking_basis=insufficient_data`, `top5=[]`.

Ранжирование относится только к фактически собранной выборке.

- `sample_complete=true` требует ровно 100 уникальных карточек с позициями 1–100.
- `research_complete=true` дополнительно требует все обложки, известный рекламный статус, полное покрытие одной метрикой ранжирования и `sample_status=ready`.
- Даже полный рейтинг не отменяет `research_complete=false` для визуального вывода.

## JSON результата

`sample-summary.json` содержит:

- размер и полноту выборки;
- полноту визуального исследования и рекламных статусов;
- паспорт региона, устройства, viewport, режима, сортировки и источника;
- запрос, даты наблюдения и период;
- покрытие MPStats и отзывов;
- основание ранжирования;
- список предупреждений;
- топ-5 с исходной позицией и значениями метрик.

Скрипт не собирает данные из сети и не читает токены. Он только валидирует подготовленный CSV и ранжирует строки.
